# Contributing

Start with the installation guide and implementation status. Keep CAD geometry, CAM, postprocessors and live controller transport separate. Add focused tests for behaviour changes. Changes to the native programs are still compared with the former Python reference, from the commit that keeps it ([The Python reference](docs/DEVELOPER.md#the-python-reference)). New protocols must distinguish export support from live control and include acknowledgement/error/abort tests before enabling hardware.

Use synthetic fixtures and simulator-only tests by default. Never put tokens, passwords, private machine credentials or generated account data in commits. Preserve third-party licence files. Document unsupported capabilities explicitly. Run `./scripts/ci-local.sh` before submitting: the hosted workflows build, test and compare the native programs, and the application checks run locally. Enable the fast pre-push gate once per clone with `git config core.hooksPath scripts/hooks`; it runs `ruff check .`, `ruff format --check .`, the native self-tests and both test suites (install the linter with `python -m pip install ruff`). Record user-visible changes in [CHANGELOG.md](CHANGELOG.md). Submit a branch and pull request with the problem, change and validation evidence; physical tests must state the actual controller and setup.

The repository-level [working instructions](AGENTS.md) and [developer handoff](docs/DEVELOPER.md) describe project schemas, extension points, the browser and simulation suites, and a worked example of extending a file reader.
