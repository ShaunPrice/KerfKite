## Desktop installers

KerfKite’s native desktop window code uses the project’s MIT licence. AppKit and WebKit come from macOS. The Linux window links the distribution's GTK 3 and loads its WebKitGTK when it starts; the package ships neither. Windows Setup redistributes Microsoft WebView2 SDK assemblies and the x64 loader from the pinned SDK NuGet package. The installer places the original Microsoft licence and third-party notices beside those files. The Microsoft Evergreen WebView2 Runtime is installed separately and has its own terms. The .NET Framework reference assemblies from the build are excluded from the installer. [Microsoft WebView2 SDK](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.4314.35)

The desktop packages include the first-party platform Studio wheel containing its C++ CAM module, its bundled vendor notices, a hash-pinned dependency list and a Go launcher. The launcher ships Go notices under `runtime-notices`. The C++ workstation server (`native/server`) is first-party code on the C++ standard library and the operating system; its phone pendant TLS relay (`packaging/pendant-tls`) is first-party Go on the Go standard library alone, under the same Go notices. First launch downloads the pinned Astral uv executable after checking the release digest. uv installs a private Python runtime and the listed third-party wheels on the user’s computer. Each downloaded distribution retains its upstream terms. The Android release APK uses a dedicated project signing certificate. [uv licence](https://github.com/astral-sh/uv/blob/0.13.1/LICENSE-MIT) · [Go licence](https://go.dev/LICENSE)

## Geometry and other native dependencies

* **PDF import.** pypdf 7.1.1 is a pure-Python dependency under BSD-3-Clause. The hashed desktop install downloads its unmodified wheel with its upstream licence. [pypdf licence](https://github.com/py-pdf/pypdf/blob/7.1.1/LICENSE)
* **STEP.** The exchange module uses Open CASCADE Technology through `cadquery-ocp-novtk`. The tested 7.9.3.1.1 wheel's metadata says Apache-2.0 for the bindings. Its Mach-O libraries include the **OCCT 7.9.3** kernel under LGPL 2.1 with the Open CASCADE exception. The exception concerns incorporation of material from headers and requires acknowledgement. Redistributing OCCT binaries still carries LGPL obligations. Supply the library licences, applicable corresponding source or compliant distribution arrangement, preserve notices and permit replacement/relinking and debugging of library modifications as the LGPL requires. Retain actual build and patch information corresponding to the binaries. [OCP licence](https://github.com/CadQuery/OCP/blob/master/LICENSE) · [OCCT 7.9.3 licence](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/LICENSE_LGPL_21.txt) · [OCCT exception](https://github.com/Open-Cascade-SAS/OCCT/blob/V7_9_3/OCCT_LGPL_EXCEPTION.txt)
* **STEP without Python.** The C++ workstation server's STEP exchange is `kerfkite-step` (`native/step/`), KerfKite's own code under MIT, linked dynamically to Open CASCADE Technology's shared libraries (LGPL 2.1 with the Open CASCADE exception; the releases are to use OCCT 7.9.3, built from the unmodified `V7_9_3` source). It is the only KerfKite program that uses Open CASCADE, and the server starts it as a separate process. A package that carries it must carry the Open CASCADE libraries as separate files that a user can replace with another build of the same release, with OCCT's notice, licence text, exception and its corresponding source or an offer of it, and the build information for those libraries. The server and the other programs contain no Open CASCADE code. [OCCT 7.9.3 source](https://github.com/Open-Cascade-SAS/OCCT/tree/V7_9_3)
* **Additional STEP-wheel libraries.** The inspected no-VTK macOS wheel contained FreeImage 3.18, LibRaw, FreeType, OpenEXR, Imath, Lerc, libjpeg, JPEG XR, Little CMS, OpenJPEG/OpenJPH, libpng, libtiff, libwebp, compression libraries and a C++ runtime. Its RECORD included no licence texts. The Studio source supplies the OCP and OCCT texts. A distributor bundling this wheel must also obtain the corresponding component notices and meet whichever upstream terms apply. FreeImage offers FIPL or GPL choices, and LibRaw offers LGPL 2.1 or CDDL 1.0. These additional notices, matching sources and any codec-specific conditions require review for the actual binary set before a bundled public distribution. [FreeImage terms](https://freeimage.sourceforge.io/license.html) · [LibRaw terms](https://www.libraw.org/about#license)
* **2D and solid geometry.** Shapely 2.2.0 is BSD-3-Clause. Its macOS wheel includes GEOS 3.14.1 and `LICENSE_GEOS` identifying LGPL 2.1. Preserve those notices, source access and library-replacement rights when distributing the libraries. Manifold 3.5.5 carries Apache 2.0 and an AUTHORS file; Studio models with it only where the compiled extension is not installed (solids and script drawings otherwise run on KerfKite's own kernels), and it remains an installed dependency. ezdxf 1.4.5 uses MIT. Retain the FontTools external licence file when distributing its font tools. [Shapely](https://github.com/shapely/shapely) · [GEOS source](https://github.com/libgeos/geos) · [Manifold licence](https://github.com/elalish/manifold/blob/master/LICENSE) · [ezdxf licence](https://github.com/mozman/ezdxf/blob/master/LICENSE)

Preserve the MPL notice and comply with its source-availability provisions if distributing the covered material. Other transitive licences are listed in the inventory. The native core has no third-party source of its own. Its JSON reader and writer (`native/core/include/kerfkite/json.hpp`, `native/core/src/json.cpp`) and the decimal conversions under them (`native/core/include/kerfkite/decimal.hpp`) are first-party code under the project's MIT licence, written from RFC 8259 and from the published methods named in those files. They replace JSON for Modern C++ 3.11.3 (MIT), which the source tree used to vendor as `native/third_party/nlohmann/json.hpp`. A `kerfkite-cam` binary or compiled extension built from a revision that still has that header contains it and must keep its licence file. The core no longer builds with GEOS either, as described next. Its DXF reader (`native/core/src/dxf.cpp`) is first-party code written from the DXF format, its PDF reader (`native/core/src/pdf_import.cpp`) and inflate (`native/core/src/inflate.cpp`) are written from ISO 32000 and RFC 1950 and 1951, with no zlib code, and its LightBurn bundle reader (`native/core/src/bundle_import.cpp`) is written from the ZIP application note, with code page 437's characters as a table of 128 values; the AutoCAD Color Index palette it gives layers (`native/core/src/aci_colors.hpp`) is a table of 256 colour values generated by `scripts/build_aci_table.py` from the palette ezdxf (MIT) lists, so that layers receive the colours Studio's Python reader gives them. The core's tables of characters (`native/core/src/unicode_tables.hpp`: the decimal digits, the characters that are not printable, `str.upper()` and the word characters) are facts of the Unicode Character Database 15.1.0 as Python 3.13's `unicodedata` and `str` methods give them, generated by `scripts/build_unicode_tables.py` so that the core reads text as the Python reference did. The Unicode data files are under the [Unicode License v3](https://www.unicode.org/license.txt), which permits this use with its notice: Copyright © 1991-2023 Unicode, Inc.

**GEOS is no longer in the native core.** Offsets, pockets and hatch fills are computed by KerfKite's own polygon kernel (`native/core/src/polygon/`, first-party code under the project's MIT licence; see [The polygon kernel](POLYGON-KERNEL.md)). The build no longer downloads or compiles GEOS, its build options are gone, and `kerfkite-cam` and the compiled extension contain no third-party code. Earlier revisions of the source built `kerfkite-cam` with GEOS 3.14.1 (GNU LGPL 2.1) by default: a binary built from such a revision contains GEOS and can only be distributed on the LGPL's terms (a notice, the licence text, GEOS's source or an offer of it, and the means to relink). This project published no such binary, so the choice between static and shared linking that was recorded here as open no longer arises.

Shapely, whose wheels carry GEOS, remains a dependency of Studio's Python code (the bullet on 2D and solid geometry above) and the reference the kernel is compared with in the validation scripts. Its terms apply to a distribution that includes those wheels, as before.

To refresh the inventory in a build environment, run `python -m pip install --dry-run --ignore-installed --report resolved.json ".[web,step,mcp]"`. Use the target OS, architecture and Python for each build, inspect the actual archives, and retain licence files even when a package's metadata reports a single permissive identifier. The recorded resolver output describes a specific platform and date.
